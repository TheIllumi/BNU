=== Part 1 – Spring Data JPA Domain & Repositories (15 marks) 

--- Task 1: Entity Design & Validation Objective: Create proper entities and map relationships using JPA. === ---


Instructions:
Implement the six entities:
Product, ProductDetail, Customer, Supplier, Sale, Purchase.
Use appropriate JPA annotations:
@Entity, @Id, @GeneratedValue
@OneToOne, @OneToMany, @ManyToOne, @JoinColumn
Map relationships:
Product ↔ ProductDetail → One-to-One.
Product ↔ Sale / Purchase → One-to-Many (from Product side, optional).
Customer ↔ Sale → One-to-Many (optional).
Supplier ↔ Purchase → One-to-Many (optional).
Add validation:
@NotBlank / @NotNull for mandatory fields (name, code, email, etc.).
@Email for email fields.
@Min(0) for currentStock, unitPrice, unitCost, etc.
@Min(1) for quantity in sale/purchase.
Use Lombok (@Data, @NoArgsConstructor, @AllArgsConstructor) if allowed.

✅ Learning Outcome: Entity design, relationships, and validation in a realistic business domain.

--- Task 4: Sales & Purchase Endpoints with Business Rules ---

Objective: Implement sales and purchase logic with inventory updates and validation.
You must enforce at least the following business rules:
Sufficient Stock for Sale
When creating a Sale:
quantity must be > 0.
product.currentStock must be ≥ quantity.
If not, return 400 BAD REQUEST with a meaningful error (e.g. “Not enough stock”).
No Sales for Inactive or Out-of-Stock Product
You cannot create a sale if:
product.active == false, OR
product.currentStock == 0.
Return 400 BAD REQUEST with a relevant message.
No Sales for Blocked Customers
If customer.blocked == true, block the sale.
Return 400 BAD REQUEST with message like: “Customer is blocked. Cannot create sale.”
Purchases Update Stock, Supplier Must Be Active
For Purchase creation:
quantity must be > 0.
supplier.active must be true.
On successful purchase: increase product.currentStock by quantity.
Sales Decrease Stock
On successful sale (status “CONFIRMED”):
decrease product.currentStock by quantity.
Note: You can implement more rules if you wish (e.g., warning if stock falls below minStockLevel).
Controllers (suggested base paths):
SaleController – /api/sales
PurchaseController – /api/purchases
Endpoints:
Create Sale
POST /api/sales
Request DTO: SaleRequestDTO { Long productId; Long customerId; int quantity; Double unitPrice; }
Backend:
Load product & customer.
Apply business rules.
Calculate totalPrice = quantity * unitPrice.
Set status = "CONFIRMED" by default.
Update product.currentStock.
Create Purchase
POST /api/purchases
Request DTO: PurchaseRequestDTO { Long productId; Long supplierId; int quantity; Double unitCost; }
Backend:
Load product & supplier.
Apply rules.
Calculate totalCost = quantity * unitCost.
Set status = "RECEIVED".
Update product.currentStock (increase).
List APIs:
GET /api/sales – list all sales.
GET /api/purchases – list all purchases.
GET /api/customers/{id}/sales – list all sales for a customer.
GET /api/suppliers/{id}/purchases – list all purchases from a supplier.
GET /api/products/{id}/sales – sales for a product (optional).
GET /api/products/{id}/purchases – purchases for a product (optional).

✅ Learning Outcome: Implementing transactional logic, updating stock, and enforcing domain rules.
